# SPEC-SCRAPBOOK-RENDER — 15-template layout system

Status: **IMPLEMENTING** (2026-07-24)

Replaces the original 5-template system (`full-bleed`, `two-up`, `three-grid`,
`photo-text`, `text-only`) with a richer 15-template palette suited to
scrapbook-style books: asymmetric hero layouts, multi-photo mosaics, and
integrated text pages.

---

## Locked decisions

**D1 — Template list and photo counts are fixed.**
Templates and their exact photo counts are the contract between the AI, the
validator, and the CSS renderer. Any new template requires changes in all four
places: `lib/specops.js` (TPL_COUNT), `lib/prompts.js` (SPEC_SHAPE +
SCAFFOLD_HEAD), `components/BookPages.js` (CSS + JSX), and this spec.

**D2 — The 15 templates.**

| template | photos | description |
|---|---|---|
| `full-bleed` | 1 | Hero image, edge to edge |
| `hero-left` | 2 | Left photo ~70% wide, right ~30% |
| `hero-right` | 2 | Right photo ~70% wide, left ~30% |
| `hero-top` | 2 | Top photo ~65% tall, bottom smaller |
| `two-equal` | 2 | Two equal columns |
| `three-banner` | 3 | Wide top, two equal below |
| `three-sidebar` | 3 | Large left, two stacked right |
| `panoramic-strip` | 3 | Three equal horizontal strips |
| `four-grid` | 4 | 2×2 equal grid |
| `four-asymmetric` | 4 | Large top-left, three smaller |
| `five-mosaic` | 5 | Large left, 2×2 right |
| `six-grid` | 6 | 3×2 grid |
| `photo-text` | 1 | Photo top ~60%, text below |
| `text-photo` | 1 | Text left column, photo right |
| `text-only` | 0 | Chapter opener / narrative page |

**D3 — Repair / fallback mapping.**
When `repairSpec` needs to pick a template for a page whose photo count changed,
it uses this default-template-by-count table. These are the simplest/safest
templates at each count:

| count | fallback template |
|---|---|
| 0 | `text-only` |
| 1 | `full-bleed` |
| 2 | `two-equal` |
| 3 | `three-banner` |
| 4 | `four-grid` |
| 5 | `five-mosaic` |
| 6+ (clip to 6) | `six-grid` |

`photo-text` and `text-photo` are never chosen by repair — they are AI choices
only, because they carry both a photo and text.

**D4 — Page padding and gap.**
All grid-style templates use `0.35in` padding around the page edge and `0.2in`
gap between photos. Full-bleed has no padding. Text areas use `0.7in` horizontal
/ `0.5in` vertical padding.

**D5 — All images are `object-fit: cover`.**
No letter-boxing, no white bars. Crop is determined by the layout proportions.
Border radius: `6px` on all grid photos; none on full-bleed.

**D6 — Caption placement.**
- `full-bleed`: caption overlay, lower-left, semi-transparent dark pill.
- All grid templates: caption below the grid, flush left, italic, smaller than
  body text. Shown only when `pg.caption` is non-empty.
- `photo-text` / `text-photo`: no caption field — the text block IS the
  annotation.
- `text-only`: no caption.

**D7 — AI page count guidance.**
The scrapbook target is **25–50 pages** for a 300-photo trip (after curation).
- Aim for an average of 3 photos per page (mix of 1, 2, 3, 4, 5, 6 photo
  templates).
- One `photo-text` or `text-photo` page per chapter is encouraged to anchor
  the narrative.
- Keep `text-only` pages to chapter openers only (one per chapter, not
  additional "day summary" pages — the chapter narrative covers that).

**D8 — Chapter structure.**
4 to 8 pages per chapter. Chapters map to days or named locations. The chapter
opener page (`bk-chapter` rendered from `ch.narrative`) is generated by the
renderer automatically — it is NOT a page in `ch.pages`. The AI must not
emit a `text-only` first page duplicating the chapter narrative.

**D9 — The renderer is purely presentational.**
`BookPages.js` never fetches data. It receives `spec` (the JSON) and
`photoUrls` (a `{ [id]: url }` map) from the parent. For on-screen preview,
`photoUrls` contains presigned preview URLs (1600px webp). For the PDF render
endpoint, they are presigned original URLs.

**D10 — Backward compatibility.**
The old 5 templates are still valid. `repairSpec` maps them: `two-up` →
`two-equal`, `three-grid` → `three-banner`. Any spec previously generated
continues to render without error.

---

## CSS approach

All layout is via CSS Grid. Each template gets its own class that is applied to
the `.bk-page` wrapper. Proportions are expressed as `grid-template-columns` /
`grid-template-rows` fractions. No flexbox magic, no absolute positioning for
grid items (only for overlays like captions and cover elements).

Page size is fixed at `8.5in × 8.5in` — square. All `in` values in CSS are
interpreted by Chromium at 96px/in for on-screen, and at the actual printer DPI
for PDF output.

---

## Validation rules (extends existing)

`validPage()` in `lib/specops.js`:
- `template` must be a key in `TPL_COUNT`.
- `photoIds.length` must equal `TPL_COUNT[template]`.
- Each photoId must exist in the valid set, not be excluded, and not already
  appear on another page.

No other structural constraints are added by this spec.
